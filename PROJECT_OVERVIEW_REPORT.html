1. Executive Summary & Problem Statement

Modern software engineering frequently involves cross-language migration, legacy modernization (e.g., converting legacy Java/C++ code into modern TypeScript or Go), and cross-stack prototyping. While standard LLM chatbots (like generic ChatGPT) can generate code translations, they suffer from three critical flaws:

  1. Lack of Structural Awareness: They perform token-by-token translation without deep Abstract Syntax Tree (AST) validation, leading to broken syntax, scope errors, and missing imports.
  2. Literal vs. Idiomatic Translation: They translate code word-for-word instead of adapting to native language paradigms (e.g., translating Python asyncio into raw loops rather than JavaScript Promise.all(), or ignoring Go error tuples).
  3. No Verification or Execution Loop: Generated code is presented statically without testing, syntax checks, complexity analysis, or sandbox execution.
💡 The Solution: Smart Code Translator
A unified, full-stack polyglot developer workbench that combines Tree-sitter AST structural extraction, Google Gemini LLM semantic reasoning, post-processing syntax validation & automated test generation, and an online multi-compiler sandbox execution engine (Wandbox) with AI Error Explanations.

4. Core Modules & Key Differentiators

1. AST-Guided Idiomatic Translation

Unlike raw text converters, the system extracts function signatures, async calls, and imports using Tree-sitter. It maps paradigms intelligently:

  • Python asyncio.gather → JS Promise.all()
  • Go val, err := func() → JS try/catch
  • Python dict.get(k, d) → JS Optional Chaining ?.
  • Java Class OOP → TypeScript Interfaces & Types

2. Online Multi-Language Sandbox

Integrated interactive IDE allowing instant code compilation and execution across 7 languages without installing local runtimes. Features:

  • Custom standard input (stdin) support
  • Real-time execution latency and exit code reporting
  • Pre-loaded starter algorithms (Sieve of Eratosthenes, Fibonacci, etc.)

3. AI Error Explainer & 1-Click Fixer

When compilation fails with standard error messages (e.g., NullPointerException, SyntaxError, IndexOutOfBounds):

  • AI pinpoints the exact offending line
  • Explains the conceptual bug in plain language
  • Provides a 1-click button to inject the corrected code directly into the editor

4. Automated Test Stub Generation

During translation, the post-processor inspects extracted AST functions and generates test suites in the target language's native framework:

  • Python → pytest test cases
  • JS/TS → vitest / jest suites
  • Java → JUnit 5 test methods
  • Go → testing package functions

5. Complexity Analysis & Optimizer

A dedicated analysis modal that determines:

  • Time Complexity: O(1), O(log n), O(n), O(n²) with mathematical reasoning.
  • Space Complexity: Memory allocation breakdown.
  • Optimization Suggestions: Recommends modern language built-ins to reduce algorithmic overhead.

6. Batch Folder & CLI Automation

Enterprise readiness features:

  • Batch Folder Translator: Recursively migrates full project folders or multi-file repositories in the browser.
  • Terminal CLI: smart-translate npm CLI for DevOps CI/CD pipeline integration.

6. Top Viva / Interview Questions & Model Answers

Q1: Why did you use Tree-sitter instead of just feeding the code to Gemini directly?
Answer: Direct LLM prompting treats code as plain text tokens and can easily hallucinate function signatures, miss variable scopes, or omit necessary imports. Tree-sitter builds a concrete syntax tree, allowing us to explicitly count nodes, extract top-level declarations, function signatures, and docstrings. We feed this structured metadata to the LLM, giving it grounded context, which significantly reduces hallucinations and syntax mismatches.
Q2: How does the Online Compiler run code safely without compromising the server?
Answer: Running user-submitted code directly on the host server poses severe security risks (fork bombs, file access, infinite loops). We mitigated this by integrating with Wandbox's isolated cloud sandbox API. The code is executed in disposable, resource-constrained containers with strict memory limits and execution timeouts. Stderr, stdout, and exit codes are securely streamed back to the client.
Q3: What makes this translation "idiomatic" rather than literal?
Answer: Literal translation preserves source syntax patterns that are anti-patterns in the target language (e.g., using indexed while-loops instead of Java Streams or Python list comprehensions). Our Prompt Factory defines strict idiomatic mapping rules: mapping Python asyncio to JS Promise.all(), Go's (val, error) multiple return convention to JavaScript try/catch blocks, and Python dictionary lookups to modern TypeScript optional chaining (?.).
Q4: What happens if MongoDB or external services fail? How resilient is the system?
Answer: The backend is built with high fault tolerance. In db.js, if MongoDB is unreachable or connection fails, the system switches automatically to an in-memory data store without crashing. In the LLM service, if the Gemini API key is missing or quota is exceeded, an intelligent local rule-based translation fallback is triggered.
